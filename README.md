### მონაცემთა გაწმენდა და დამუშავება (Cleaning & Preprocessing)

#### 1. გამოტოვებული მნიშვნელობების (NA) მქონე სვეტების დადროპვა
სვეტები რომლებსაც 98%-ზე მეტი NaN ჰქონდათ წავშალე Transaction data-დან სანამ identity-სთან დავ-merge-ავდი. დამერჯვამდე ეს იმიტომ გავაკეთე, რომ identity-ში არსებული NaN ინფორმაციის მომცემია და მისი დადროპვა არაა კარგი იდეა. თუ identity-ში მონაცემების სიმცირეა ეს შეიძლება თაღლითობის მანიშნებელი იყოს. სვეტების მსგავსი გასუფთავების მეთოდი გამოვიყენე მხოლოდ logistic regression და random forest, რადგანაც xgboost-ს და decision tree-ს შეუძლიათ transaction-ის NaN-ებთან თავისით გამკლავება. 

<img width="1464" height="861" alt="image" src="https://github.com/user-attachments/assets/a1ae71c9-ef35-43ec-9002-a484c65b8795" />

#### 2. NA მნიშვნელობების შევსების სტრატეგია
NA მნიშვნელობები xgboost-ის მოდელში არ შემივსია, რადგანაც თვითონაც უმკლავდება. decision tree-ის მოდელში ყველაფერი შევავსე მედიანით ordinal encoding-ის შემდეგ ხოლო, logistic regression და random forest-ში რიცხვითი მონაცემები შევავსე მედიანით და კატეგორიულ მონაცემებში ჩავწერე "missing".

#### 3. უსარგებლო სვეტების მოცილება
TransactionID, რომელიც მხოლოდ იდენტიფიკაციისთვის გამოიყენება დავდროპე რადგანაც სტატისტიკური მონაცემი არაა.

### Feature Engineering

* **hour:** შევქმენი ახალი სვეტი TransactionDT-დან ფორმულით: $hour = (TransactionDT // 3600) % 24$ ეს გვიჩვენებს დღის რომელ საათზე მოხდა ტრანზაქცია. Fraud-ის შემთხვევები შეიძლება გარკვეულ საათებში უფრო ხშირად ხდებოდეს, ამიტომ ეს feature მოდელს დროით პატერნებს აძლევს.

* **identity_missing:** შევქმენი ახალი სვეტი, რომელიც ითვლის რამდენი id_ სვეტია ცარიელი თითოეულ row-ში. IEEE-CIS Fraud Detection-ში identity მონაცემები ხშირად აკლია. ეს missing-ობა თვითონ შეიძლება მნიშვნელოვანი სიგნალი იყოს, რადგან ზოგი ტრანზაქცია უფრო ანონიმურია.

* **uid:** შევქმენი მომხმარებლის მსგავსი იდენტიფიკატორი card1 და addr1 სვეტების გაერთიანებით. ეს არ არის ნამდვილი მომხმარებლის ID, მაგრამ გვეხმარება მსგავსი ტრანზაქციების დაჯგუფებაში.

* **uid_amt_diff:** შევქმენი deviation feature. ეს გვიჩვენებს რამდენად განსხვავდება მიმდინარე ტრანზაქცია ამ მომხმარებლის ჩვეულებრივი ქცევისგან. თუ ტრანზაქციის თანხა ძალიან განსხვავებულია, ეს შეიძლება fraud-ისთვის მნიშვნელოვანი სიგნალი იყოს.

  <img width="896" height="653" alt="image" src="https://github.com/user-attachments/assets/6341fb81-9427-42a4-9ed4-f62c3a5606f1" />

* **OneHotEncoder:** გამოვიყენე კატეგორიულ სვეტებზე, რათა რიცვით მონაცემებად გადამეკეთებინა. გამოვიყენე მხოლოდ logistic regression და xgboost მოდელებში, ხოლო decision tree-სა და random forest-ში გამოვიყენე ordinal encoding, რადგანაც OHE ძალიან ბევრ სვეტს ამატებს დატას და რადგანაც ისედაც დიდი დატა გვქონდა კიდევ უფრო გაბევრება არ მინდოდა, შესაბამისად რადგანაც ხეებისთვის ordinal encoding-ის შედეგად მიღებულ ორდერინგს მნიშვნელობა არ აქვს მისი გამოყენება ვამჯობინე. xgboost-შიც ამის გამოყენება ჯობდა ალბათ, მაგრამ გვიან მომაფიქრდა და თან ისედაც კარგი შედეგი ჰქონდა xgboost-ს.

### Feature Selection

#### 1. uselessFeatureDropper
ყველა მოდელში მაქვს კლასი, რომელიც ისეთ სვეტებს დროპავს, რომელთა მნიშვნელობებიც მუდმივია, ან ვარიანსია ნულის ტოლი, ასეთი სვეტები ტრენინგ დატაში არცერთი არ იყო, შესაბამისად ამ კლასის არსებობა გავლენას ვერ ახდენს მოდელზე.

#### 2. კორელაციის ფილტრი (Threshold = 0.95)
ამოვიღე ის ცვლადები, რომელთა შორის კორელაცია 0.95-ზე მეტი იყო. 
თუ ორი ცვლადი ერთმანეთთან ძალიან ძლიერადაა დაკავშირებული, ისინი მოდელისთვის ერთსა და იმავე ინფორმაციას ატარებენ. ეს კი აფუჭებს მოდელის ინტერპრეტაციას. ეს ფილტრი გამოვიყენე მხოლოდ logistic regression-ის მოდელში, რადგანაც ხის მოდელებს არ სჭირდებათ. სრეშჰოლდად 0.95 იმიტომ ავირჩიე, რომ მხოლოდ ძალიან მსგავსი სვეტები წამეშალა და მნიშვნელოვანი ინფორმაცია არ დამეკარგა.
